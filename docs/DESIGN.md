# 译镜 TransLens · 产品设计文档

> 学术文本「回译检查 + 多版本对照」工作台
> 版本 v0.4 · 2026-11-19 · 状态：M1 已实现（见 §11）
> 提示词：[`docs/PROMPTS.md`](PROMPTS.md)（中英双语）· 使用与部署：[`README.md`](../README.md)

**v0.4 的变化：格式全部交给模型**

- 删除本地 LaTeX 处理（清理 / 保护 / 占位符）。**本地只按空行分段，原文一个字都不改**；格式的去除或保留完全由模型按提示词里的格式规则完成（§6）。
- 格式处理只剩两个选项：「去除无关格式标记」（默认）和「保留原格式」，规则都可修改、可重置。
- 对照粒度从「句」改为「段」：句子切分也是本地处理，在 LaTeX 里容易切错（如把 `\footnote{...}` 切断）。输出协议改为 `<seg id="n">…</seg>` 块，段内可以跨多行（§7.2）。
- 自定义宏不再在本地展开，改为「宏说明」写进提示词，由模型理解。

**v0.3 的变化（根据试用反馈）**

- **方向、翻译模式、格式处理三者独立**。方向默认「自动（中 ⇄ 英）」，选翻译模式不再改动方向；内置模式都不再绑定方向（原「中译英（学术写作）」改为「论文表达（可直接放进论文）」）。
- 默认翻译模式改为 **「中英互译检查（忠实直译）」**，每个模式都附一句「适用场景」说明。
- 「LaTeX 处理」改为 **「格式处理」**：新增并默认使用 **「去除无关格式标记（模型处理）」**，规则覆盖 LaTeX、Markdown、HTML、PDF 复制痕迹；模型处理时也按句对照。
- 不含 LaTeX 的文本不再被当作 LaTeX 处理（例如 `2.3%` 里的 `%` 不会被当成注释）。
- 提示词与格式规则都可在设置里修改，内置内容可一键「重置为原始提示词 / 规则」；工具条上有「✎」直达编辑、「?」说明本地处理与模型处理的区别。

**v0.2 相对设计稿的变化**

- 前端框架改为 **Vite + 原生 TypeScript**，不用 React/dockview（理由见 §10.1）。
- LaTeX 处理从三种变为**四种**，新增「交给模型清理」，沿用用户提供的参考规则（§6.1）。
- **DeepSeek** 成为首选模型服务：内置模板、余额查询、思考过程提示、缓存命中统计（§7.4）。
- 提示词改为中英双语等价版本，结构参考了用户的提示词（[PROMPTS.md](PROMPTS.md)）。
- 已实现部分原定 P1/P2 功能：多工作区、参考稿、段落缓存与增量重译、译文历史、AI 差异解读、费用估算、代理。

## 0. 一句话定位

一个**纯前端、数据只存在浏览器本地**的翻译工作台：自己填 API Key，用预设提示词把 AI 润色后的英文（含 LaTeX）**忠实地**翻回中文；多个版本在同一屏幕里并排、对比差异，确认润色没有偷偷改掉你的意思。

可部署到 Cloudflare Pages / GitHub Pages / Vercel 等任何静态托管，不需要 VPS、数据库或后端。

## 1. 用户与场景

### 1.1 目标用户

- **主要**：用 LaTeX / Overleaf 写英文论文的中文研究者（研究生、青年教师），习惯用 ChatGPT / Claude / DeepSeek 等润色。
- **次要**：精读英文文献的人；需要把中文初稿译成英文的人。

### 1.2 核心场景

| # | 场景 | 用户此刻想要 | 现有工具的问题 |
|---|---|---|---|
| S1 | **润色回译检查** | 把润色后的段落翻回中文，看意思有没有被改 | 通用翻译会"顺手润色"，掩盖语义偏移；LaTeX 符号被乱翻或干扰阅读 |
| S2 | **多版本对比** | 原稿 / GPT 版 / Claude 版 / 导师改版，哪里不同、哪个好 | 只能开多个窗口来回切，靠肉眼找差异 |
| S3 | **原意核对** | 对照自己的中文初稿，检查英文版有没有漏掉或多出信息 | 基本没有工具做这件事 |
| S4 | 文献精读 | 从 PDF 复制段落翻译 | PDF 复制的文本断行、连字符错乱 |
| S5 | 中译英初稿 | 中文段落 → 学术英文 | 术语前后不一致 |

### 1.3 用户故事（节选）

- 我粘贴一段润色后的 LaTeX，选"清理 LaTeX"，一键得到干净的中文直译：公式原样保留，`\cite{}` 变成 `[引用]`，`\textbf{}` 消失只留文字。
- 我把原稿、GPT 版、Claude 版放在三个并排的标签页里，打开"差异"，每个版本相对原稿的增删词被高亮，回译后的中文也高亮差异。我一眼看到 GPT 版多了 *consistently*，回译成"持续地"，这是原文没有的结论。
- 我把标签命名为"原稿 / GPT 润色 / 导师修改"，关掉浏览器，下次打开一切都在。
- 我确认没有任何服务器保存我的论文：请求从浏览器直接发给我选的模型服务。

## 2. 痛点与对策

| 痛点 | 设计对策 |
|---|---|
| 翻译器"自作主张"润色，回译看不出问题 | 默认提示词「回译检查」：忠实直译，保留语气强度（may/might、significantly/slightly、up to/consistently），不纠错，歧义处加【注】 |
| LaTeX 等格式符号干扰阅读 | 由模型按可编辑的格式规则去除或保留；本地不改动原文（§6） |
| 多版本对比靠肉眼 | 对比基准 + 原文/译文两层词级差异高亮 + 同步滚动 + 句级对齐（§8） |
| 长段落的译文和原文对不上号 | 逐句编号协议，悬停一句即高亮对应译句（§7.2） |
| 改一个词就要整段重翻、浪费钱 | 段落级缓存，只重翻改动过的段落 |
| 浏览器跨域（CORS）、担心 Key 泄露 | 默认直连；可选自部署 Cloudflare 代理；Key 只存本地、可加密、导出默认不含 Key（§7.5、§9） |
| 纯本地存储怕丢数据 | 自动保存到 IndexedDB + 一键导出/导入 + 申请持久化存储 |

## 4. 信息架构与核心概念

```
工作区 Workspace（如「论文A · Introduction」）
 ├─ 布局 Layout ............ 拆分树：Split(方向, 比例[]) / Group(标签[], 当前标签)
 ├─ 标签页 Tab ............. 一个翻译单元 = 原文 + 设置 + 译文历史
 │   ├─ 设置 .............. 继承工作区默认值，可单独覆盖（模型/提示词/LaTeX/方向）
 │   └─ 译文版本 Run[] ..... 每次翻译一条：模型、提示词快照、逐句结果、用量
 ├─ 对比基准 baseTabId
 └─ 启用的术语表
全局：模型服务 Provider[] · 提示词 Prompt[] · LaTeX 规则与宏 · 外观
```

- **窗格（Group）**：屏幕上的一个矩形区域，顶部是自己的标签栏，可以容纳多个标签，一次显示一个。和 VS Code 的编辑器组一样，用户不用重新学。
- **设置继承**：工作区定默认值，标签只存与默认值不同的部分，新建标签不必重复选模型和提示词。

├──────────────────────────┤ ├──────────────────────────┤ ├────────────────────────┤

### 5.2 顶栏

从左到右：Logo ｜ 工作区切换（下拉：新建、重命名、删除）｜ 布局预设 5 个图标 ｜ 同步滚动 ｜ 差异（含对比层级：原文/译文/两者）｜ ▶ 翻译所有标签（次要按钮；超过一个标签时先列出确认）｜ ＋ 新标签 ｜ ⚙ 设置 ｜ 主题图标（跟随系统 / 浅色 / 深色）。

顶栏按钮高 34px，比正文按钮大一号。「设置」是填 API Key 的唯一入口，用主题色描边、带齿轮图标和文字；还没有配置任何模型服务时，按钮右上角显示红点。窄屏时依次隐藏「同步滚动」「新标签」的文字（≤1180px、≤900px），≤480px 只保留图标。

### 5.3 标签栏

- 标签：色点 + 名称 + 状态（⟳ 翻译中 / ● 已过期 / ⚠ 出错）+ ★ 基准 + ×。
- **双击改名**，回车确认、Esc 取消。
- 右键菜单：重命名、颜色、设为对比基准、复制标签、在右侧/下方打开、关闭。
- 标签栏右侧：向右拆分 ⫿、向下拆分 ⊟、最大化 ⤢。
- 新建标签默认命名"版本 A / B / C…"。

### 5.4 标签页内部

```
┌ [自动▾] [中英互译检查▾ ✎] [DeepSeek▾] [格式：去除无关标记▾ ?] [布局] …… [翻译 ⌘↵] ┐
├ 原文 · 3 段 · 812 字符 · 自动识别：英→中              [整理断行] [AI 解读差异] ┤
│  始终可直接编辑（文本框），改动自动保存；不需要点「编辑」                    │
│  下面叠一层逐字对齐的高亮底层：差异模式标新增（绿底）与删除位置（红竖线），  │
│  悬停译文某段时原文对应段落标黄；点击原文某段，对应译文段落高亮并滚动到位    │
├─────────────────────── 可拖动分隔 ─────────────────────────────────────┤
├ 译文 · 完成 · 1.2k tokens · 3.1s              [历史 v3▾] [复制] [双语] ┤
│  逐段显示；【注】用浅色显示                                              │
└───────────────────────────────────────────────────────────────────────┘
```

标签有以下几种状态：

| 状态 | 表现 |
|---|---|
| 空 | 原文框里有粘贴提示 |
| 翻译中 | 译文逐段流式出现；按钮变为"停止"；原文仍可编辑 |
| 完成 | 原文仍是可编辑文本框，与译文按段联动 |
| 已过期 | 译文顶部黄条："原文已修改 · 重新翻译" |
| 出错 | 红条：原因 + 解决建议（如"疑似跨域，去设置开启代理"） |

### 5.5 拆分与拖拽规则

- 拖动分隔条实时调整，单个窗格最小约 160px；**双击分隔条均分**。
- 把标签拖到另一个窗格上，显示 5 个落点（上/下/左/右/中）的半透明预览：落在边缘就拆出新窗格，落在中间就并入该窗格。
- 窗格空了自动移除；只剩一个子节点的拆分节点自动折叠。
- 布局和比例随工作区自动保存。
- 移动端（宽度 < 768px）：不拆分，标签横向滑动切换；对比时上下堆叠并显示差异。

### 5.6 对比模式

- 打开"差异"后，基准标签显示 ★，其他可见标签相对基准高亮：**新增：绿底；删除：红色删除线**。
- 对比层级：原文 / 译文 / 两者。选项：忽略大小写、忽略标点、忽略 LaTeX。
- 句级对齐（P1）：悬停任意一句，所有窗格里对应的句子一起黄色高亮；同步滚动以对齐的句子为锚点。
- AI 差异解读（P2）：选两个标签 → "解读差异" → 输出表格：差异点 / A 的说法 / B 的说法 / 影响（语气增强、事实变化、信息新增…）。

### 5.7 设置（模态框，左侧导航）

1. **模型服务**：列表 + "从模板添加"。字段有名称、协议、Base URL、API Key（可显示/隐藏）、模型（可"获取列表"）；高级项有温度、max tokens、并发数、自定义 Header、单价、是否走代理。带"测试连接"按钮。
2. **提示词**：内置模板只读，可"复制为自定义"后修改；编辑器旁列出可用变量；可"试运行"。
3. **LaTeX**：默认模式、各元素的处理规则（§6.2）、自定义宏映射，以及一个样例框，粘贴后实时显示处理结果。
4. **术语表**：表格编辑，可导入 CSV/TSV。
5. **外观**：主题、字号、行高、正文字体（无衬线/衬线）、界面语言。
6. **数据与隐私**：存储占用、导出/导入、清除、Key 存储方式、隐私说明。

## 6. 格式处理（全部交给模型）

### 6.1 原则

原文里常带有与意思无关的格式标记：LaTeX 命令、Markdown 符号、HTML 标签、从 PDF 复制来的引用编号和断行等。v0.2–v0.3 曾在本地用程序处理 LaTeX（占位符保护公式），但本地规则覆盖不全、容易改坏原文。**v0.4 起，格式的去除和保留全部交给模型，用提示词约束；本地只按空行分段，原文一字不改。**

### 6.2 两种方式

| 方式 | 发给模型的内容 | 提示词里的格式规则 | 译文呈现 |
|---|---|---|---|
| **去除无关格式标记**（默认） | 原文原样 | 删除 LaTeX 引用/标签/排版命令和注释、只留标题与强调里的文字、去掉 Markdown/HTML 标记、去掉 PDF 引用编号/行号/页眉页脚并接回断词断行；公式保留 | 干净的译文，只保留公式 |
| **保留原格式** | 原文原样 | 所有命令、环境、标签、注释、公式、引用、换行原样保留，只翻译文字（含 `\textbf{…}`、`**…**` 等内部文字） | 带原格式的译文，可直接放回原文件 |

完整规则见 [PROMPTS.md](PROMPTS.md)。两套规则在「设置 → 格式处理」中可编辑（中英文各一份），随时重置。

### 6.3 自定义宏

论文里的自定义宏（如 `\ours`）模型不认识。用户在设置里写「宏说明」（`\ours = XNet`），原文出现该宏时，说明和术语表一起写进提示词。去除格式时模型把宏替换为对应文字，保留格式时原样保留。原文里自带的 `\newcommand` 定义模型本身也能看到。

### 6.4 风险与对策

| 风险 | 对策 |
|---|---|
| 模型改写公式 | 规则明确要求公式保持不变；「差异」功能可以对照检查 |
| 模型漏段、合并段 | `<seg id>` 编号协议 + 解析时发现缺段自动补译一次 |
| 规则不合用户的格式习惯 | 规则可编辑，可重置 |

## 7. 翻译引擎

### 7.1 流水线

```
原文
 → ① 按空行分段（本地唯一的处理，段内内容原样保留）
 → ② 查段落缓存（hash(系统提示词 + 模型 + 段落)），命中的直接复用
 → ③ 未命中的段落按约 2400 字符组块
 → ④ 拼提示词：翻译模式 + 格式规则 + 命中的术语 / 宏说明 + 输出格式 + 示例
 → ⑤ 并发请求（默认 2 路，流式），每块内的段落放进 <seg id="n">
 → ⑥ 流式解析 <seg> 块，逐段渲染
 → ⑦ 缺失的段落自动补译一次
 → ⑧ 保存译文版本（最近 10 次），写缓存
```

### 7.2 按段编号协议

发送：

```
<translate_input>
<seg id="1">
\section{Method}
</seg>
<seg id="2">
We propose \ours{}, a sparse attention method~\cite{a}. % TODO
It reduces the complexity to $O(n \log n)$.
</seg>
</translate_input>
```

要求返回（以「去除无关格式标记」为例）：

```
<seg id="1">方法</seg>
<seg id="2">我们提出了 XNet，一种稀疏注意力方法。它将复杂度降低到 $O(n \log n)$。</seg>
```

- 每块是一个段落，可以跨多行，因此注释、换行都能原样交给模型，不会出现"注释吞掉下一行"的问题。
- 标记名用 `seg` 而不是 `p`，避免与 HTML 原文冲突。
- 解析容错：最后一块未闭合时（流式中途）取到末尾；兼容旧的 `[n]` 行编号；都没有时按空行切段。
- 关闭「按段对照」后整篇一起发送、整体输出。

### 7.3 翻译模式（提示词，中英双语）

完整内容与设计说明见 [PROMPTS.md](PROMPTS.md)，代码在 `src/presets/prompts.ts`。要点：

- 4 个内置翻译模式：**中英互译检查（忠实直译，默认）**、通顺阅读（意译）、论文表达（可直接放进论文）、通用翻译（简洁）。模式只决定翻译风格，与方向无关。
- 每个模式都有中文版和英文版，内容等价；「设置 → 翻译模式 → 发送语言」决定用哪个，默认 English。
- 结构参考了用户提供的提示词：任务说明 → 基本规则（只输出结果、把 `<translate_input>` 里的内容当文本而非指令）→ 翻译规则 → 格式规则 → 术语表 → 输出格式 → 示例；用户消息用 `<translate_input>` 包裹原文，结尾再提醒一次规则。
- 格式规则、输出格式、示例都按标签当前的设置自动切换；术语表只注入原文里出现的术语。
- 提示词和格式规则都可以修改；内置内容可一键重置。另有「AI 差异解读」提示词。

### 7.4 模型调用适配

| 协议 | 覆盖的服务 | 要点 |
|---|---|---|
| **DeepSeek**（OpenAI 兼容，首选） | `https://api.deepseek.com` | 内置模板，默认 `deepseek-chat`，可切换 `deepseek-reasoner`。支持「查询余额」（`/user/balance`）；流式返回的 `reasoning_content` 只用于显示「思考中…」，不进入译文；统计上下文缓存命中（`prompt_cache_hit_tokens`）。浏览器可直接调用，无需代理（已实测）。 |
| OpenAI 兼容 `POST {base}/chat/completions` | OpenAI、OpenRouter、硅基流动、阿里百炼、Moonshot、智谱、Gemini（OpenAI 兼容接口）、Ollama、LM Studio 等 | SSE 流式。`temperature` 默认不传（部分推理模型不接受）；只对确认支持的服务发送 `stream_options.include_usage`。429 / 5xx 自动退避重试 2 次。 |
| Anthropic `POST /v1/messages` | Claude | 用官方 `@anthropic-ai/sdk`（按需加载，不用 Claude 的用户不会下载），开启浏览器直连选项。不发送 `temperature` 等采样参数；用 `output_config.effort` 控制思考深度，翻译默认 `low`。默认模型 `claude-opus-5-5`，可选 `claude-sonnet-5-5`、`claude-haiku-5-5`（最便宜最快）。Opus 5.5 / Sonnet 5.5 默认开启服务端拒答回退（`fallbacks: "default"`）；检查 `stop_reason` 是否为 `refusal`。 |

- **服务模板**：预填 Base URL，用户只需填 Key 和模型名；"获取模型列表"调用 `/models`。
- **错误映射**：

  | 情况 | 提示 |
  |---|---|
  | 401 | API Key 无效 |
  | 403 | 无权限或地区限制 |
  | 404 | Base URL 或模型名错误 |
  | 429 | 被限流，指数退避自动重试（最多 3 次） |
  | 5xx | 服务端错误，自动重试 |
  | `TypeError: Failed to fetch` | 多半是跨域（CORS），提示开启代理或换服务 |

- **取消**：用 `AbortController`；关闭标签时自动取消进行中的请求。

### 7.5 跨域（CORS）与可选代理

浏览器直连要求服务端允许跨域。多数主流服务允许（Anthropic 需要一个特殊请求头，官方 SDK 会自动加），少数不允许。方案：

- **默认直连**；"测试连接"能识别出跨域失败并给出提示。
- **可选代理**：项目自带一个 Cloudflare Pages Function `functions/api/proxy.ts`，由用户自己部署、自己掌控：
  - 只转发，不记录、不存储，流式透传。
  - 必须配置环境变量 `PROXY_ALLOWED_HOSTS`（目标域名白名单），防止被当成开放代理滥用。
  - 可选 `PROXY_TOKEN` 访问口令。
  - 不配置就返回 404，也就是默认关闭。
- **本地模型**：Ollama 需要设置 `OLLAMA_ORIGINS` 放行站点来源，之后可以完全离线使用，数据不出本机。

### 7.6 缓存与用量

- 缓存键 = hash(块文本 + 提示词 + 模型 + 命中术语)。命中时直接复用，并标注"来自缓存"。
- 用量优先读接口返回的 `usage`，没有就按字符估算；结合服务单价显示费用。

## 8. 对比算法

- **原文**：先按清理模式得到纯文本，再按词做 diff（jsdiff `diffWords`）。
- **译文**：用 `Intl.Segmenter('zh', { granularity: 'word' })` 分词后 diff（`diffArrays`），比逐字 diff 好读得多。
- **句级对齐**（P1）：在两个版本的句子序列上做带相似度的动态规划。相似度用词 bigram 的 Dice 系数，阈值 0.3；结果可以是一对一、一对多或无对应。用于联动高亮、同步滚动和"只看改动句"。
- **性能**：diff 放到 Web Worker 里算，输入变化后防抖 300ms。

## 9. 数据与隐私

### 9.1 存储位置

| 数据 | 位置 | 说明 |
|---|---|---|
| 工作区、标签、译文历史、缓存 | IndexedDB（Dexie） | 容量大，结构化 |
| 设置、提示词、术语表、服务配置 | IndexedDB | 启动时读入内存 |
| UI 偏好（主题、上次打开的工作区） | localStorage | 小、同步读取 |
| API Key | 默认随服务配置存储；可选口令加密 / 仅本次会话 | 导出时默认剔除 |

### 9.2 数据模型

完整类型定义见 [`src/types.ts`](../src/types.ts)。层级关系：

```
AppState
 ├─ workspaces: Workspace[]          工作区：名称、布局树、标签、对比基准
 │   └─ tabs: Record<id, Tab>         标签：名称、颜色、类型（翻译 / 参考稿）、原文、设置
 │       ├─ runs: Run[]               译文历史（最近 10 次）：逐段结果、用量、费用
 │       └─ analysis?                 最近一次 AI 差异解读
 ├─ providers: Provider[]            模型服务：协议、Base URL、Key、模型、并发、单价、是否走代理
 ├─ prompts: PromptPreset[]          提示词预设（中英双语）
 ├─ rules / macros / glossary        LaTeX 规则、自定义宏、术语表
 └─ ui                               主题、字号、同步滚动、差异开关
IndexedDB: kv（应用状态）· cache（段落级翻译缓存，键 = hash(系统提示词 + 模型 + 段落原文)）
```

### 9.3 隐私承诺（设置页"关于隐私"中展示）

- 无后端、无账号、无统计埋点、无第三方脚本或字体 CDN（全部打包进站点）。
- 网络请求只有一种：浏览器 → 你配置的模型服务（或你自己部署的代理）。
- 严格的 CSP（Cloudflare `_headers`）：`script-src 'self'`，防止注入脚本窃取 Key；`connect-src` 放行 `https:` 和本机端口，以支持任意模型服务。
- 提醒用户：纯本地意味着清理浏览器数据会丢失内容，所以要定期导出；应用会申请持久化存储。

```
# public/_headers
/*
  Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; font-src 'self'; connect-src 'self' https: http://localhost:* http://127.0.0.1:*; frame-ancestors 'none'; base-uri 'none'; form-action 'none'
  Referrer-Policy: no-referrer
  X-Content-Type-Options: nosniff
  Permissions-Policy: camera=(), microphone=(), geolocation=()
```

## 10. 技术方案

### 10.1 技术栈（v0.2 实际采用）

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite 8 + TypeScript 7 | 产物是纯静态文件，适配任何静态托管 |
| UI | **原生 TypeScript + 轻量 DOM 构造函数**（不用框架） | 原型已验证自研布局完全满足需求；运行时零第三方依赖，体积小、加载快，也更容易审计「没有把数据发到别处」 |
| 格式处理 | 全部由模型按提示词处理；本地只按空行分段 | v0.4 起删除本地 LaTeX 处理，避免本地规则改坏原文 |
| 窗格 / 标签 / 拖拽停靠 | 自研布局树（Split / Group） | 支持任意嵌套拆分、拖动分隔条、拖动标签停靠到上下左右中、布局预设、最大化，约 300 行 |
| 编辑器 | 原生 textarea + 逐字对齐的高亮底层 | 原文始终可编辑；差异与段落联动画在底层，不影响输入；CodeMirror 留作后续可选 |
| 存储 | 自写 IndexedDB 封装，失败时退回 localStorage，再退回内存 | 无依赖 |
| Diff | 自写 LCS + 语义清理 + `Intl.Segmenter` 中文分词 | 无依赖，结果比逐字 diff 好读 |
| 模型调用 | OpenAI 兼容用 `fetch` + SSE 解析；Claude 用官方 SDK（动态加载） | |
| 测试 | Vitest（核心逻辑） | |

原设计稿中的 React + dockview 方案仍然可行；`src/core` 与 UI 无关，将来如需迁移框架可直接复用。

### 10.3 部署

- **Cloudflare Pages（推荐）**：连接 GitHub 仓库，构建命令 `npm run build`，输出目录 `dist`；或在本地运行 `npx wrangler pages deploy dist`。
